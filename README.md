# krisha.kz scraper

Парсер объявлений о недвижимости с [krisha.kz](https://krisha.kz/). Обходит страницы поиска (с любыми фильтрами),
при желании открывает каждое объявление и сохраняет результат в CSV, JSON Lines или JSON.

## Установка

Нужен Python 3.10+.

Windows (PowerShell):

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

macOS / Linux:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Если PowerShell пишет, что выполнение сценариев отключено: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

## Использование

Настройте фильтры на сайте (город, комнаты, цена…), скопируйте ссылку из адресной строки и передайте её парсеру:

```bash
# Первые 3 страницы продажи квартир в Алматы → CSV
python -m krisha_scraper https://krisha.kz/prodazha/kvartiry/almaty/ --pages 3 -o data/almaty.csv

# Аренда в Астане, с открытием каждого объявления (параметры, описание, координаты, фото)
python -m krisha_scraper https://krisha.kz/arenda/kvartiry/astana/ --details -o data/astana.jsonl

# Несколько поисков сразу, не больше 500 объявлений
python -m krisha_scraper https://krisha.kz/prodazha/kvartiry/almaty/ https://krisha.kz/prodazha/kvartiry/astana/ --limit 500 -o data/listings.csv

# Продолжить прерванный сбор в тот же файл
python -m krisha_scraper https://krisha.kz/prodazha/kvartiry/almaty/ --details -o data/almaty.csv --resume

# Одно объявление
python -m krisha_scraper https://krisha.kz/a/show/123456789 -o data/one.json
```

Все опции: `python -m krisha_scraper --help`.

| Опция | Что делает |
|---|---|
| `-o, --output` | файл результата; формат по расширению: `.csv`, `.jsonl`, `.json` (по умолчанию `data/listings.csv`) |
| `-p, --pages N` | обойти не больше N страниц поиска (по умолчанию — все) |
| `--start-page N` | начать с N-й страницы |
| `-d, --details` | открывать каждое объявление (в ~20 раз больше запросов) |
| `--limit N` | остановиться, когда в файле N объявлений (с `--resume` считаются и сохранённые раньше) |
| `--resume` | продолжить сбор в тот же файл: уже сохранённые объявления остаются и не скачиваются заново |
| `--delay S` | пауза между запросами, по умолчанию 1.5 с (±20%) |
| `--retries N` | повторы при сетевых ошибках, HTTP 5xx и ограничении частоты 429/468 (учитывается `Retry-After`) |

### Остановка и сохранение

- **Ctrl+C** останавливает обход и сохраняет всё собранное. Повторный Ctrl+C во время записи файла игнорируется.
  На macOS/Linux так же работают `kill` и закрытие терминала.
- CSV и JSON во время работы сохраняются на диск раз в минуту, через временный файл — поэтому файл на диске всегда
  целый. Если процесс убит без возможности сохраниться (закрыли окно терминала на Windows, выключился компьютер),
  теряется не больше последней минуты.
- `.jsonl` пишется построчно — его удобно брать для долгих прогонов с `--details`.
- Чтобы продолжить прерванный сбор, запустите ту же команду с `--resume`: каждый поиск продолжится со страницы, на
  которой остановился (это хранится в `<имя>.progress.json` рядом с файлом), уже пройденные поиски пропускаются.
  Без `--resume` новый запуск начинает файл заново, а прошлый файл переносится в `<имя>.prev.<расширение>`
  (например, `almaty.prev.csv`).
- Если CSV открыт в Excel, промежуточное сохранение пропускается до следующей минуты. Если файл так и не удалось
  записать в конце, все данные остаются рядом в `<имя>.unsaved-<дата-время>.<расширение>` — закройте Excel и
  переименуйте его. Следующие запуски такие файлы не трогают, а `--resume` сам продолжит по самому полному из них.

### Ограничения сайта

- **HTTP 468** — так krisha.kz отвечает, когда запросов слишком много. Парсер ждёт 30, 60 и 120 секунд и повторяет запрос.
  Если сайт продолжает отказывать, обход останавливается с сообщением, а собранное сохраняется. Запустите позже
  ту же команду с `--resume` (лучше и с `--delay 3`) — уже сохранённое скачиваться не будет.
- **Выдача сдвигается.** По умолчанию сайт показывает сначала свежие объявления, и продавцы постоянно «поднимают» их
  наверх. Пока идёт долгий сбор (особенно с `--details`), страницы сдвигаются: часть объявлений повторяется (парсер их
  пропускает), а поднятые с ещё не пройденных страниц можно пропустить. Для полного сбора добавляйте к ссылке
  сортировку по цене — `sort_by=price-asc`, её поднятия не сдвигают:
  `https://krisha.kz/prodazha/kvartiry/almaty/?sort_by=price-asc`.
- **Не больше 1000 страниц** (~20 000 объявлений) на один поиск. Если найдено больше, парсер предупредит. Чтобы
  собрать всё, разбейте поиск фильтрами (диапазоны цены, районы, комнаты) и передайте несколько ссылок сразу —
  повторы между ними сохраняются один раз.

## Что собирается

Со страницы поиска:

| Поле | Пример |
|---|---|
| `id`, `url` | `1000001`, `https://krisha.kz/a/show/1000001` |
| `title` | `2-комнатная квартира · 56 м² · 5/9 этаж` |
| `rooms`, `area_m2`, `floor`, `floors_total` | `2`, `56.0`, `5`, `9` — разобраны из заголовка (у новостроек этажа в заголовке нет) |
| `price`, `price_text` | `25000000`, `25 000 000 ₸` (для «от …» — нижняя граница) |
| `address`, `city` | `Алмалинский р-н, Абая 10`, `Алматы` |
| `updated` | `5 окт.` — дата последнего поднятия объявления (не дата публикации) |
| `description_preview`, `photo` | начало описания, превью фото |

С `--details` дополнительно открывается страница объявления:

| Поле | Описание |
|---|---|
| `address` | полный адрес: `Алматы, Алмалинский р-н, Абая 10` |
| `lat`, `lon` | координаты |
| `created_at`, `updated_at` | дата создания и последнего поднятия: `2026-09-20`, `2026-10-05` |
| `price_m2` | цена за м² (у аренды — за м² в месяц) |
| `seller_type` | `owner` — хозяин, `specialist` — агент/риелтор |
| `status` | `live` — активно, `archive` — в архиве |
| `description` | полное описание |
| `photos` | все фото (в CSV — через ` \| `) |
| параметры | `Тип дома`, `Год постройки`, `Этаж`, `Санузел`… — в CSV отдельными колонками, в JSON — объект `params` |

CSV сохраняется в UTF-8 с BOM, поэтому Excel открывает кириллицу без танцев.

Объявление, найденное по нескольким ссылкам (или продублированное платным «горячим» блоком), сохраняется один раз.

Телефоны и имена продавцов не собираются: это персональные данные.

## Аккуратность

- Парсер соблюдает `robots.txt` сайта (включая шаблоны `*` и `$`): запрещённые адреса не загружаются.
- Между запросами есть пауза; не ставьте `--delay` меньше секунды, чтобы не нагружать сайт и не получить бан.
- Перед использованием данных проверьте пользовательское соглашение krisha.kz.

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Структура:

- `krisha_scraper/parsers.py` — разбор HTML (селекторы `div.a-card`, `.offer__*`, JSON из `<script id="jsdata">`).
  Селекторы сверены с реальными страницами krisha.kz 2024–2026 годов; если сайт поменяет вёрстку, править нужно здесь.
  Фикстуры в `tests/fixtures/` повторяют реальную разметку, данные в них выдуманные.
- `krisha_scraper/client.py` — HTTP: пауза, повторы, robots.txt.
- `krisha_scraper/scraper.py` — обход страниц поиска и объявлений.
- `krisha_scraper/storage.py` — запись в CSV / JSONL / JSON.
- `krisha_scraper/cli.py` — командная строка.
